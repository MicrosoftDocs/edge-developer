## CSS features

The following new Cascading Style Sheets (CSS) features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### `corner` shorthand properties

The new `corner` CSS shorthand property sets both the radius and the shape of an element's corners in a single declaration, by combining the `border-radius` and `corner-shape` properties.

For example:

```css
.card {
  /* Equivalent to: border-radius: 20px; corner-shape: squircle; */
  corner: 20px squircle;
}
```

The following additional shorthand properties let you set the radius and shape of specific corners:

* Per-corner shorthands: `corner-top-left`, `corner-top-right`, `corner-bottom-left`, and `corner-bottom-right`.
* Physical edge shorthands, such as `corner-top` and `corner-bottom`, which set the two corners of an edge.
* Logical edge shorthands, such as `corner-block-start` and `corner-block-end`, which set the two corners of an edge, based on the writing mode.

See also:
* [The corner shorthand](https://drafts.csswg.org/css-borders-4/#propdef-corner) in _CSS Borders and Box Decorations Module Level 4_.
* [corner-shape CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/corner-shape) at MDN.
* [border-radius CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/border-radius) at MDN.


<!-- ------------------------------ -->
#### `text-decoration-inset` property

The `text-decoration-inset` CSS property controls how far underlines, overlines, and line-through decorations are inset from or extended beyond the start and end edges of an element's text.

`text-decoration-inset` supports the following types of values:

* `auto`, which lets the browser determine the appropriate inset based on the element's text and surrounding context.
* A length value, such as `20px`.
* A percentage value, such as `10%`.
* Either one or two values.  The first value sets the start offset.  The second value, if specified, sets the end offset.

This lets you adjust decoration spacing and create reveal effects with native text decorations, instead of using background gradients or additional elements.

See also:
* [text-decoration-inset CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/text-decoration-inset) at MDN.


<!-- ------------------------------ -->
#### Custom string value for `text-overflow`

The `text-overflow` CSS property now accepts a string value, to specify the custom text that's displayed when the content of an element overflows and is clipped.

Previously, you could only use the `clip` or `ellipsis` values.  A custom string lets you create overflow indicators that better fit your content, for example:

```css
.summary {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: " (more)";
}
```

See also:
* [text-overflow CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/text-overflow) at MDN.
* [text-overflow](https://drafts.csswg.org/css-overflow-4/#text-overflow) in _CSS Overflow Module Level 4_.


<!-- ------------------------------ -->
#### `position-visibility: anchor-valid` and `anchor-visible`

When using CSS anchor positioning, the `position-visibility` CSS property controls when an anchor-positioned element is hidden.  The `position-visibility` property now supports the following values:

* `anchor-valid` (new) - The anchor-positioned element is only displayed if its default anchor element exists, and the element can therefore be positioned relative to it.

* `anchor-visible` - The anchor-positioned element is only displayed if its default anchor element is at least partially visible.  This value replaces the `anchors-visible` value.

The plural `anchors-visible` value is now deprecated, and is an alias of `anchor-visible`.  Use `anchor-visible` instead.

See also:
* [position-visibility CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/position-visibility) at MDN.
* [CSS anchor positioning](https://developer.mozilla.org/docs/Web/CSS/Guides/Anchor_positioning) at MDN.
* [position-visibility](https://drafts.csswg.org/css-anchor-position-1/#position-visibility) in _CSS Anchor Positioning Module Level 1_.

## HTML features

The following new HTML features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### Icon-only mode for the `<camera>`, `<microphone>`, and `<geolocation>` elements

The `<camera>`, `<microphone>`, and `<geolocation>` HTML elements now support the `displaymode` attribute, which you can use to render these elements as compact, icon-only buttons, without text.

Icon-only buttons are useful in space-constrained layouts, such as map controls or floating video toolbars.  In icon-only mode, the elements keep the same security guarantees, and remain fully accessible to screen readers.

See also:
* [&lt;geolocation&gt; HTML element](https://developer.mozilla.org/docs/Web/HTML/Reference/Elements/geolocation) at MDN.
* [`<camera>` and `<microphone>` elements](./153.md#camera-and-microphone-elements) in _Microsoft Edge 153 web platform release notes (Sep. 10, 2026)_.
* [Media capture HTML elements](https://w3c.github.io/mediacapture-extensions/#media-capture-html-elements) in _Media Capture and Streams Extensions_.

## Web APIs

The following new Web API features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### Updated HTML insertion and streaming methods

The following HTML insertion and streaming methods provide a more coherent way to dynamically insert HTML into an existing document:

* Positional methods, which take HTML as an argument and effectively replace `insertAdjacentHTML()`:
  * `beforeHTML()` and `beforeHTMLUnsafe()`
  * `afterHTML()` and `afterHTMLUnsafe()`
  * `appendHTML()` and `appendHTMLUnsafe()`
  * `prependHTML()` and `prependHTMLUnsafe()`
  * `replaceWithHTML()` and `replaceWithHTMLUnsafe()`
* Streaming methods, which return a `WritableStream` object that parses the HTML text that you write to it:
  * `streamHTML()` and `streamHTMLUnsafe()`
  * `streamAppendHTML()` and `streamAppendHTMLUnsafe()`
  * `streamPrependHTML()` and `streamPrependHTMLUnsafe()`
  * `streamReplaceWithHTML()` and `streamReplaceWithHTMLUnsafe()`
  * `streamBeforeHTML()` and `streamBeforeHTMLUnsafe()`
  * `streamAfterHTML()` and `streamAfterHTMLUnsafe()`

Additionally, you can set the `runScripts` option to `true` when calling any of the unsafe HTML insertion or streaming methods, to allow the method to run scripts in a similar fashion to `createContextualFragment()`.

Trusted Types policies can also override the scripting mode and the sanitizer that are used by these methods.

Before these methods, you could already update HTML dynamically from script by using multiple disjointed APIs, each with its own subtle differences.  For example, you can:
* Partially update an element by using `insertAdjacentHTML()`.
* Sanitize HTML by using `setHTML()`.
* Execute scripts by using `createContextualFragment()`.
* Stream HTML by using a detached document.

Such multiple, disjointed APIs can be confusing and hard to use.  Such APIs can also cause security issues when not used well.

See also:
* [Dynamic markup - revamped](https://github.com/WICG/declarative-partial-updates/blob/main/dynamic-markup-revamped-explainer.md)
* [Element: setHTML() method](https://developer.mozilla.org/docs/Web/API/Element/setHTML) at MDN.


<!-- ------------------------------ -->
#### Sanitizer API: `javascriptURLs` option

The Sanitizer API now provides the `javascriptURLs` configuration option and the `setJavascriptURLs()` method, to control whether `javascript:` URLs that are used for navigation, such as in the `href` attribute of an `<a>` element, are removed when sanitizing HTML.

Previously, whether `javascript:` URLs were removed depended on the method that you used: the safe methods, such as `setHTML()`, always removed them, and the unsafe methods, such as `setHTMLUnsafe()`, never removed them.  Now, removing `javascript:` URLs is an explicit part of the sanitizer configuration, which you can use with any method.

If you don't use the new option, the behavior is unchanged.

See also:
* [HTML Sanitizer API](https://developer.mozilla.org/docs/Web/API/HTML_Sanitizer_API) at MDN.
* [Sanitizer](https://developer.mozilla.org/docs/Web/API/Sanitizer) at MDN.
* [setJavascriptURLs()](https://html.spec.whatwg.org/#dom-sanitizer-setjavascripturls) in _HTML Standard_.


<!-- ------------------------------ -->
#### HTML-in-canvas

The HTML-in-canvas API lets you draw HTML elements into a `<canvas>` element, so that you can use the canvas to customize how HTML content is rendered, while keeping the content accessible, interactive, and correctly laid out.

For example, you can use HTML-in-canvas to render styled text in charts, rich content in creative tools, in-game menus, or HTML content on surfaces within a 3D scene.

HTML-in-canvas provides the following primitives:
* Attributes to opt the descendants of a `<canvas>` element into layout and drawing.
* Methods to draw elements into the canvas: `drawElementImage()` for 2D canvas contexts, and equivalent methods for WebGL and WebGPU.
* A `paint` event, which fires when the drawn elements need to be updated in the canvas.
* Methods to synchronize the geometry of the drawn elements with the DOM, for hit testing and accessibility.

See also:
* [HTML-in-Canvas explainer](https://github.com/WICG/html-in-canvas)
* [HTMLCanvasElement](https://developer.mozilla.org/docs/Web/API/HTMLCanvasElement) at MDN.


<!-- ------------------------------ -->
#### Long Animation Frames API: style and layout durations

The Long Animation Frames API now reports how much time was spent on style and layout calculations, so that you can distinguish style time from layout time when analyzing slow frames:

* `PerformanceLongAnimationFrameTiming` objects have the new `styleDuration` and `layoutDuration` properties, which report the time that's spent recalculating styles and updating layout, as part of the rendering update.
* `PerformanceScriptTiming` objects have the new `forcedStyleDuration` and `forcedLayoutDuration` properties, which report the time that's spent on style and layout calculations that were forced synchronously by scripts.

See also:
* [Long animation frame timing](https://developer.mozilla.org/docs/Web/API/Performance_API/Long_animation_frame_timing) at MDN.
* [PerformanceLongAnimationFrameTiming](https://developer.mozilla.org/docs/Web/API/PerformanceLongAnimationFrameTiming) at MDN.


<!-- ------------------------------ -->
#### Pages with active WebSockets can enter the back/forward cache

Pages that have active WebSocket connections can now be stored in the back/forward cache (bfcache).  When such a page is stored in the bfcache, its active WebSocket connections are closed.

Previously, an active WebSocket connection prevented a page from entering the bfcache, which made back and forward navigations slower for these pages.

If your page uses WebSockets, make sure that it can reconnect when it's restored from the bfcache.  To do this, listen to the `pageshow` event, and check whether the event's `persisted` property is `true`.

This change is being rolled out gradually.

See also:
* [bfcache](https://developer.mozilla.org/docs/Glossary/bfcache) in the MDN glossary.
* [Window: pageshow event](https://developer.mozilla.org/docs/Web/API/Window/pageshow_event) at MDN.
* [The WebSockets API (WebSockets)](https://developer.mozilla.org/docs/Web/API/WebSockets_API) at MDN.


<!-- ------------------------------ -->
#### CORS enforcement for the Background Fetch API

The Background Fetch API now enforces Cross-Origin Resource Sharing (CORS).

This ensures that Background Fetch requests are subject to the same security policies, such as Local Network Access checks.  This prevents sites from bypassing CORS (and other security policy checks) by using Background Fetch instead of regular Fetch.

See also:
* [Background Fetch API](https://developer.mozilla.org/docs/Web/API/Background_Fetch_API) at MDN.
* [Fetch API](https://developer.mozilla.org/docs/Web/API/Fetch_API) at MDN.
* [Fetch](https://fetch.spec.whatwg.org/) standard.
* [Cross-Origin Resource Sharing (CORS)](https://developer.mozilla.org/docs/Web/HTTP/Guides/CORS) at MDN.


<!-- ------------------------------ -->
#### `ProgressEvent` in service workers

The `ProgressEvent` interface is now available in service workers.  You can use the `ProgressEvent()` constructor in a service worker to create progress events with the `lengthComputable`, `loaded`, and `total` properties.

This aligns service workers with other worker contexts and with the XMLHttpRequest Standard.

See also:
* [ProgressEvent](https://developer.mozilla.org/docs/Web/API/ProgressEvent) at MDN.
* [Service Worker API](https://developer.mozilla.org/docs/Web/API/Service_Worker_API) at MDN.


<!-- ------------------------------ -->
#### Web Bluetooth: `BluetoothRemoteGATTServer` is an `EventTarget`

The `BluetoothRemoteGATTServer` interface now inherits from `EventTarget`, and therefore exposes the `addEventListener()`, `removeEventListener()`, and `dispatchEvent()` methods.

This allows connection-level events to be dispatched directly on the GATT server object.

See also:
* [BluetoothRemoteGATTServer](https://developer.mozilla.org/docs/Web/API/BluetoothRemoteGATTServer) at MDN.
* [Web Bluetooth API](https://developer.mozilla.org/docs/Web/API/Web_Bluetooth_API) at MDN.


<!-- ------------------------------ -->
#### WebGPU: `atomic-vec2u-min-max` feature

The `atomic-vec2u-min-max` WebGPU feature allows you to use 64-bit atomic minimum and maximum operations on `atomic<vec2u>` values, in WebGPU Shading Language (WGSL) shaders.

This lets you implement algorithms that require 64-bit atomics, without requiring full support for 64-bit integers.

See also:
* [WebGPU API](https://developer.mozilla.org/docs/Web/API/WebGPU_API) at MDN.
* [atomic-vec2u-min-max](https://www.w3.org/TR/webgpu/#dom-gpufeaturename-atomic-vec2u-min-max) in _WebGPU_, at W3C.
