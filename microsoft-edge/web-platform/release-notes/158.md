## CSS features

The following new Cascading Style Sheets (CSS) features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### `flow-start` and `flow-end` alignment keywords

The `flow-start` and `flow-end` keywords are now accepted by CSS alignment properties, as aliases of the existing `flex-start` and `flex-end` keywords.

These keywords refer to the edges of a container at which content placement starts and ends.  This is useful when placement is reversed, such as in CSS grid lanes layouts that use `fill-reverse` or `track-reverse`.  Because the keywords are aliases, `flex-start` and `flex-end` now follow the logical start and end directions in any layout mode where those differ from the physical directions, and not only in flexbox.

When a value that uses either `flex-start`, `flex-end`, `flow-start`, or `flow-end` is serialized, the result uses `flow-start` or `flow-end`.

See also:
* [item-flow row vs. column in masonry layouts](https://github.com/w3c/csswg-drafts/issues/12803) in _CSS Working Group issues_.
* [Add flow-start and flow-end alignment keywords](https://github.com/w3c/csswg-drafts/pull/14539) in _CSS Working Group pull requests_.


<!-- ------------------------------ -->
#### `::highlight(*)` universal selector

The `::highlight(*)` CSS pseudo-element selector matches the highlight pseudo-elements of all custom highlights, regardless of their names.

The `*` argument adds zero specificity.  This means that styles you declare by using `::highlight(*)` act as a base style, which rules that name a specific highlight can override.

For example, to style all custom highlights with a yellow background, and then override the style of a highlight named `error`:

```css
::highlight(*) {
  background-color: yellow;
}

::highlight(error) {
  background-color: pink;
}
```

See also:
* [::highlight() CSS pseudo-element](https://developer.mozilla.org/docs/Web/CSS/Reference/Selectors/::highlight) at MDN.
* [Custom highlight pseudo-element](https://drafts.csswg.org/css-pseudo-4/#selectordef-highlight-highlight-name-selector) in _CSS Pseudo-Elements Module Level 4_.


<!-- ------------------------------ -->
#### Media element pseudo-classes

The following CSS pseudo-classes match `<audio>` and `<video>` elements based on their state:
* `:playing`
* `:paused`
* `:seeking`
* `:buffering`
* `:stalled`
* `:muted`
* `:volume-locked`

Use them to style media elements, or their surrounding UI, without needing JavaScript to track the state, for example to dim a video while it's buffering:

```css
video:buffering {
  opacity: 0.5;
}
```

See also:
* [:playing CSS pseudo-class](https://developer.mozilla.org/docs/Web/CSS/Reference/Selectors/:playing) at MDN.
* [:paused CSS pseudo-class](https://developer.mozilla.org/docs/Web/CSS/Reference/Selectors/:paused) at MDN.
* [:seeking CSS pseudo-class](https://developer.mozilla.org/docs/Web/CSS/Reference/Selectors/:seeking) at MDN.
* [:buffering CSS pseudo-class](https://developer.mozilla.org/docs/Web/CSS/Reference/Selectors/:buffering) at MDN.
* [:stalled CSS pseudo-class](https://developer.mozilla.org/docs/Web/CSS/Reference/Selectors/:stalled) at MDN.
* [:muted CSS pseudo-class](https://developer.mozilla.org/docs/Web/CSS/Reference/Selectors/:muted) at MDN.
* [:volume-locked CSS pseudo-class](https://developer.mozilla.org/docs/Web/CSS/Reference/Selectors/:volume-locked) at MDN.


<!-- ------------------------------ -->
#### `closest-corner` and `farthest-corner` radii for `circle()` and `ellipse()`

The `circle()` and `ellipse()` CSS basic-shape functions now accept the `closest-corner` and `farthest-corner` radius keywords, in addition to the existing `closest-side` and `farthest-side` keywords.

These keywords resolve to the distance from the center of the shape to the nearest or farthest corner of the reference box.  This matches the behavior of the same keywords in the `radial-gradient()` function.  You can use them in the `clip-path`, `shape-outside`, and `offset-path` properties.

For example, to clip an element to a circle that reaches the farthest corner of the element:

```css
.badge {
  clip-path: circle(farthest-corner at 25% 25%);
}
```

See also:
* [circle() CSS function](https://developer.mozilla.org/docs/Web/CSS/Reference/Values/basic-shape/circle) at MDN.
* [ellipse() CSS function](https://developer.mozilla.org/docs/Web/CSS/Reference/Values/basic-shape/ellipse) at MDN.
* [Basic shape functions](https://drafts.csswg.org/css-shapes-1/#basic-shape-functions) in _CSS Shapes Module Level 1_.


<!-- ------------------------------ -->
#### `object-fit` and `object-position` for SVG documents in `<object>` and `<embed>`

The `object-fit` and `object-position` CSS properties now apply to Scalable Vector Graphics (SVG) documents that are loaded by using an `<object>` or `<embed>` element.  The SVG document is sized and positioned inside the content box of the element, in the same way as the content of an `<img>` element.

Previously, Microsoft Edge ignored both properties for embedded SVG documents, and always stretched the document viewport to fill the whole content box.

See also:
* [object-fit CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/object-fit) at MDN.
* [object-position CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/object-position) at MDN.
* [Embedded content rendering rules](https://html.spec.whatwg.org/multipage/rendering.html#embedded-content-rendering-rules) in the _HTML_ standard.

## HTML features

The following new HTML features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### `<install>` element

The `<install>` HTML element is a browser-rendered control that lets users install a web app, without you having to write JavaScript.  Because the browser renders the control, it gets a stronger signal of the user's intent than when handling `beforeinstallprompt` events.

By default, the element installs the web app that's associated with the current document.  To offer the installation of another web app, such as in an app catalog, use the `manifest` attribute to specify the URL of the web app manifest, and optionally, the `manifestid` attribute to specify the manifest ID.  The content of the element is fallback content:

```html
<install
  manifest="https://music.example/manifest.webmanifest"
  manifestid="https://music.example/app">
  <a href="https://music.example/">Open Music Example</a>
</install>
```

The `<install>` element is the declarative counterpart of the `navigator.install()` method.  See [Web Install API](#web-install-api).

Administrators can control this feature in two ways:
* The [WebAppInstallByUserEnabled](/deployedge/microsoft-edge-policies/webappinstallbyuserenabled) policy can disable web app installation by users, including installations that are started by the `<install>` element and the `navigator.install()` method.
* The `web-app-installation` permissions policy can allow or disallow the use of this feature on origins that the administrator controls, such as internal sites and iframes.

See also:
* [Web Install](https://wicg.github.io/install-element) specification at WICG.
* [Web Install API](#web-install-api) in _Microsoft Edge 158 web platform release notes (Nov. 19, 2026)_.

## SVG features

The following new Scalable Vector Graphics (SVG) features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### `side` attribute for SVG `<textPath>`

The `side` attribute of the SVG `<textPath>` element lets you choose which side of a path the text follows.  Setting `side="right"` reverses the direction of the path for text layout.  This makes it easy to place text inside or outside of a circular path, without duplicating or manually reversing the path data.

For example:

```html
<svg viewBox="0 0 200 200">
  <path id="circle" d="M 100,100 m -75,0 a 75,75 0 1,1 150,0 a 75,75 0 1,1 -150,0" fill="none" />
  <text>
    <textPath href="#circle" side="right">Text on the other side of the path</textPath>
  </text>
</svg>
```

See also:
* [side attribute](https://developer.mozilla.org/docs/Web/SVG/Reference/Attribute/side) at MDN.
* [textPath SVG element](https://developer.mozilla.org/docs/Web/SVG/Reference/Element/textPath) at MDN.
* [The side attribute](https://w3c.github.io/svgwg/svg2-draft/text.html#TextPathElementSideAttribute) in _Scalable Vector Graphics (SVG) 2_.

## Web APIs

The following new Web API features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### Web Install API

The Web Install API lets a website prompt the user to install a web app.  The `navigator.install()` method installs the web app that's associated with the current document, or, by passing a manifest URL and an optional manifest ID, a different web app.  This enables cross-origin web app installation, and is a better developer experience than handling `beforeinstallprompt` events.

For example, an app catalog can offer to install a web app that's identified by its manifest URL:

```javascript
await navigator.install({
  manifest: "https://music.example/manifest.webmanifest",
  manifestId: "https://music.example/app"
});
```

The user must always confirm the installation.

The `navigator.install()` method is the imperative counterpart of the `<install>` element.  See [`<install>` element](#install-element).

Administrators can control this feature in two ways:
* The [WebAppInstallByUserEnabled](/deployedge/microsoft-edge-policies/webappinstallbyuserenabled) policy can disable web app installation by users, including installations that are started by the `navigator.install()` method and the `<install>` element.
* The `web-app-installation` permissions policy can allow or disallow the use of this feature on origins that the administrator controls, such as internal sites and iframes.

See also:
* [Web Install](https://wicg.github.io/install-element) specification at WICG.
* [Web Install API](https://chromestatus.com/feature/5183481574850560) at Chrome Platform Status.


<!-- ------------------------------ -->
#### Permissions policy: `focus-without-user-activation`

The `focus-without-user-activation` permissions policy gives embedders control over programmatic focus changes that are made by embedded content.

When the policy is denied for the frame that initiates the focus change, the following programmatic focus changes are blocked, unless that frame has transient user activation or focus is already within its subtree:
* Calls to `element.focus()` and `window.focus()`.
* The `autofocus` attribute.
* The focusing steps for dialogs and popovers.

This doesn't prevent dialogs or popovers from opening.  Focus changes that are initiated by the user, such as clicking or tabbing, are never affected.  The existing restriction on `autofocus` in cross-origin iframes is unchanged.  The policy can further restrict `autofocus`, but allowing the policy doesn't enable `autofocus` in a cross-origin frame.

Set the policy by using the `Permissions-Policy` HTTP response header or the `allow` attribute of an `<iframe>` element.  A parent frame that has focus can still pass focus to a child iframe, even when the child frame has the policy denied.  After a frame has focus, it can move focus within its own subtree.

For example, to block an embedded frame from moving focus without user activation:

```html
<iframe src="https://example.com/widget" allow="focus-without-user-activation 'none'"></iframe>
```

See also:
* [Permissions-Policy header](https://developer.mozilla.org/docs/Web/HTTP/Reference/Headers/Permissions-Policy) at MDN.
* [focus-without-user-activation](https://html.spec.whatwg.org/#focus-without-user-activation-feature) in the _HTML_ standard.


<!-- ------------------------------ -->
#### Prerender cross-origin iframes

Microsoft Edge can now prerender cross-origin iframes, instead of delaying them until the page is activated.  To opt in, include the `Supports-Loading-Mode: prerender-cross-origin-frames` HTTP response header in the response of the top-level page.  The browser then prerenders all of the cross-origin frames of that page.

Use this in cases where you embed a cross-origin iframe that's important to your application, to avoid delaying its loading when the page is activated.

See also:
* [Prerendering](https://wicg.github.io/nav-speculation/prerendering.html) specification at WICG.
* [Prerendering cross-origin iframes](https://chromestatus.com/feature/5112398709129216) at Chrome Platform Status.


<!-- ------------------------------ -->
#### WebAudio: Incremental rendering for `OfflineAudioContext`

The `OfflineAudioContext` interface now supports incremental rendering.  Instead of allocating the whole audio buffer up front, the audio graph data is processed and delivered in chunks.  This lowers memory requirements when you process large amounts of audio data, particularly on devices with limited memory.

See also:
* [OfflineAudioContext: startRendering() method](https://developer.mozilla.org/docs/Web/API/OfflineAudioContext/startRendering) at MDN.
* [startRendering()](https://webaudio.github.io/web-audio-api/#dom-offlineaudiocontext-startrendering) in the _Web Audio API_ specification.


<!-- ------------------------------ -->
#### Direct Sockets: Source-Specific Multicast

The Direct Sockets API now supports Source-Specific Multicast (SSM).  When you join a multicast group, you can optionally specify a source address, to receive UDP packets only from that source.  Without a source address, the `joinGroup()` method uses Any-Source Multicast (ASM), which receives packets from any source that sends to the group.

SSM is essential for using multicast outside of private networks.  It simplifies packet routing, and it lets the network filter traffic by source address, which helps mitigate spoofing and denial-of-service attacks.

The Direct Sockets API is available to Isolated Web Apps.

See also:
* [Direct Sockets](https://wicg.github.io/direct-sockets/#dom-multicastgroupoptions-sourceaddress) specification at WICG.


<!-- ------------------------------ -->
#### WebTransport: Congestion control

The `WebTransport()` constructor now accepts a `congestionControl` option, and `WebTransport` instances have a matching read-only `congestionControl` property.  Set the option to `"default"`, `"throughput"`, or `"low-latency"`, to let the browser select congestion-control behavior that suits your application for each session.

For example:

```javascript
const transport = new WebTransport(url, { congestionControl: "low-latency" });
```

See also:
* [WebTransport: congestionControl property](https://developer.mozilla.org/docs/Web/API/WebTransport/congestionControl) at MDN.
* [WebTransport() constructor](https://developer.mozilla.org/docs/Web/API/WebTransport/WebTransport) at MDN.
* [congestionControl](https://www.w3.org/TR/webtransport/#dom-webtransportoptions-congestioncontrol) in _WebTransport_ at W3C.


<!-- ------------------------------ -->
#### WebTransport: Reliability attributes

The `reliability` property and the static `supportsReliableOnly` property are now available on `WebTransport`.  They tell you what kinds of connections are supported:
* The static `WebTransport.supportsReliableOnly` property indicates whether the browser supports WebTransport over exclusively reliable connections.  In Microsoft Edge, it returns `false`, because a session that's established successfully uses HTTP/3, and supports unreliable datagrams.
* The `reliability` property of a `WebTransport` instance indicates whether the established session supports unreliable transport, such as datagrams.  It initially returns `"pending"`, and changes to `"supports-unreliable"` after an HTTP/3 WebTransport connection is established.

See also:
* [WebTransport: reliability property](https://developer.mozilla.org/docs/Web/API/WebTransport/reliability) at MDN.
* [reliability](https://www.w3.org/TR/webtransport/#dom-webtransport-reliability) in _WebTransport_ at W3C.


<!-- ------------------------------ -->
#### WebTransport: Anticipated concurrent incoming streams

You can now tell WebTransport how many incoming streams you expect to have open at once, by using hints in the `WebTransport()` constructor.  The browser uses these hints to configure the initial QUIC stream allowance.  This reduces the risk that a server that needs high stream concurrency is blocked by the initial stream limit.

See also:
* [WebTransport() constructor](https://developer.mozilla.org/docs/Web/API/WebTransport/WebTransport) at MDN.
* [WebTransport configuration](https://w3c.github.io/webtransport/#web-transport-configuration) in _WebTransport_ at W3C.


<!-- ------------------------------ -->
#### WebTransport: Draining

The `draining` property of `WebTransport` is a promise that resolves when the server indicates that the WebTransport session will be gracefully retired.  Use this signal to establish a replacement session while the existing streams and the current session remain usable.

For example:

```javascript
transport.draining.then(() => {
  // Start a new session, and migrate your streams to it.
});
```

See also:
* [WebTransport: draining property](https://developer.mozilla.org/docs/Web/API/WebTransport/draining) at MDN.
* [Handling session draining](https://github.com/w3c/webtransport/blob/main/explainer.md#11-handling-session-draining) in the _WebTransport explainer_.
* [draining](https://w3c.github.io/webtransport/#dom-webtransport-draining) in _WebTransport_ at W3C.


<!-- ------------------------------ -->
#### WebTransport: Receive stream statistics

The `WebTransportReceiveStream` interface is now available.  It's a `ReadableStream` subclass that's used for incoming unidirectional streams, and for the readable side of bidirectional streams.  Its `getStats()` method returns per-stream byte counters:
* `bytesReceived` reports the number of bytes that were received from the network.
* `bytesRead` reports the number of bytes that were delivered to your application.

See also:
* [WebTransportReceiveStream](https://developer.mozilla.org/docs/Web/API/WebTransportReceiveStream) at MDN.
* [WebTransportReceiveStream](https://w3c.github.io/webtransport/#webtransportreceivestream) in _WebTransport_ at W3C.


<!-- ------------------------------ -->
#### WebTransport: Keying material export

The `exportKeyingMaterial()` method of `WebTransport` lets your application derive cryptographic keying material that's bound to an established WebTransport session.  The method takes binary `label` and `context` values, and a requested output length, and returns a promise that resolves to a `Uint8Array`.

The `label` and `context` values can each be up to 255 bytes, and the output length can range from 1 through 4096 bytes.

For WebTransport over HTTP/3, the stream ID of the WebTransport `CONNECT` stream is included in the Transport Layer Security (TLS) exporter context.  This ensures that separate WebTransport sessions derive different keying material, even when they share the same HTTP/3 connection.

See also:
* [WebTransport: exportKeyingMaterial() method](https://developer.mozilla.org/docs/Web/API/WebTransport/exportKeyingMaterial) at MDN.
* [exportKeyingMaterial()](https://www.w3.org/TR/webtransport/#dom-webtransport-exportkeyingmaterial) in _WebTransport_ at W3C.
