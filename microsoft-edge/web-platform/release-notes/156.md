## CSS features

The following new Cascading Style Sheets (CSS) features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### `:navigation-source` pseudo-class

When using the View Transitions API, use the `:navigation-source` pseudo-class to style the element that initiated the navigation, such as a link, button, or form.

The `:navigation-source` CSS pseudo-class applies to the element that initiated the navigation throughout the navigation process.

See also:
* [The :navigation-source pseudo-class](https://drafts.csswg.org/css-navigation-1/#navigation-source-pseudo-class) in _CSS Navigation Matching_.
* [View Transition API](https://developer.mozilla.org/docs/Web/API/View_Transition_API) at MDN.


<!-- ------------------------------ -->
#### `random()` function

The `random()` CSS function brings generative randomness to CSS, allowing you to generate a random numeric value within a specified range.

For example, you can use `random()` to scatter elements randomly within their container:

```css
.dot {
  /* Position each dot randomly */
  position: absolute;
  top: random(0%, 100%);
  left: random(0%, 100%);
}
```

By default, each call to the `random()` function resolves to a new, distinct value.  You can override this default behavior by passing a seed value as the function's first parameter, to control how random values are shared across properties and elements.

See also:
* [random() CSS function](https://developer.mozilla.org/docs/Web/CSS/Reference/Values/random) at MDN.


<!-- ------------------------------ -->
#### `text-decoration-inset` property

The `text-decoration-inset` CSS property controls how far underlines, overlines, and line-through decorations are inset from or extended beyond the start and end edges of an element's text.

`text-decoration-inset` supports the following types of values:

* `auto`, which lets the browser determine the appropriate inset based on the element's text and surrounding context.
* A length value, such as `20px`.
* A percentage value, such as `10%`.
* Either one or two values.  The first value sets the start offset.  The second value, if specified, sets the end offset.

See also:
* [text-decoration-inset CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/text-decoration-inset) at MDN.


<!-- ------------------------------ -->
#### Optional descriptors in `@property` rules

In a `@property` rule, you can omit the `syntax`, `inherits`, or `initial-value` descriptors.  The default values make it possible to remove boilerplate code.

Omitted descriptors default to the following values:

* `syntax` defaults to `*` (the universal syntax).
* `inherits` defaults to `true`.
* `initial-value` defaults to `initial-value`, which is guaranteed to be invalid.  This default allows properties that are typed to use the `var()` function with a fallback value.

The above defaults also work when registering a custom property from JavaScript, by using `CSS.registerProperty()`. 

See also:
* [@property CSS at-rule](https://developer.mozilla.org/docs/Web/CSS/Reference/At-rules/@property) at MDN.
* [CSS: registerProperty() static method](https://developer.mozilla.org/docs/Web/API/CSS/registerProperty_static) at MDN.
* [Guaranteed-invalid value](https://drafts.csswg.org/css-variables-2/#guaranteed-invalid-value) in _CSS Custom Properties for Cascading Variables Module Level 2_.


<!-- ------------------------------ -->
#### Single-axis scroll containers

The `overflow` CSS property now supports setting a scrollable value, such as `scroll`, together with a second value, `clip`.  For example: `overflow: scroll clip;`

Setting `overflow: scroll clip` allows an element with `position: sticky` to be constrained by different scroll containers per axis.  For example, use this to create a table that keeps both the column and row headers in view, while the user scrolls through the content.

Previously, the `overflow` property didn't provide a way to make a scroll container responsible for a single axis only.  This affected features that depend on scroll containers, such as elements with `position: sticky`.

See also:
* [Single-Axis Scroll Containers explainer](https://github.com/explainers-by-googlers/single-axis-scroll-containers)
* [`overflow` CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/overflow) at MDN.


<!-- ------------------------------ -->
#### `scroll-snap-type: pair` to snap to a single element

The `scroll-snap-type` CSS property now supports the `pair` value.

```css
.scroller {
  scroll-snap-type: pair mandatory;
}
```

The `pair` value treats scroll snapping along the x and y axes as a pair.  Instead of independently picking a snap target along the x axis, and a snap target along the y axis, snapping selects a single element in both axes.

See also:
* [scroll-snap-type CSS property](https://developer.mozilla.org/docs/Web/CSS/Reference/Properties/scroll-snap-type) at MDN.
* [pair](https://drafts.csswg.org/css-scroll-snap-1/#valdef-scroll-snap-type-pair) in _CSS Scroll Snap Module Level 1_.

## Web APIs

The following new Web API features are included in Microsoft Edge.


<!-- ------------------------------ -->
#### Failed module imports can be retried

You can now retry failed module imports, for example after a network failure.

Previously, a failure to import a module was cached, and retrying importing the same module returned the same failure.

The module loading behavior now enables failed module imports to be manually retried.  This includes:

* Dynamic imports, by using the `import()` function.
* Dynamically inserting a `<script src="..." type="module">` element.
* Any static import, using the `import` statement, when present in either of the above contexts.

See also:
* [JavaScript modules](https://developer.mozilla.org/docs/Web/JavaScript/Guide/Modules) at MDN.
* [import()](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Operators/import) at MDN.
* [import](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Statements/import) at MDN.
* [module](https://developer.mozilla.org/docs/Web/HTML/Reference/Elements/script/type#module) in _`<script type>` HTML attribute_, at MDN.


<!-- ------------------------------ -->
#### Compression dictionary transport Updates

When fetching a compression dictionary via a `<link rel="compression-dictionary">` element, Microsoft Edge now:
* Uses `compression-dictionary` as a request destination.
* Properly sets the values for the request `mode`, `credentials`, `referrer`, and `referrerpolicy`.
* Takes into account the `crossorigin` and `referrer` attributes that are set on the `<link rel="compression-dictionary">` element.

See also:
* [Compression Dictionary Transport](https://developer.mozilla.org/docs/Web/HTTP/Guides/Compression_dictionary_transport) at MDN.
* [rel="compression-dictionary" HTML attribute value](https://developer.mozilla.org/docs/Web/HTML/Reference/Attributes/rel/compression-dictionary) at MDN.


<!-- ------------------------------ -->
#### IndexedDB: SQLite backend

For new data stores, Microsoft Edge now uses SQLite instead of the IndexedDB API, as the underlying storage engine on the backend.

The IndexedDB API itself remains unchanged; only the underlying storage engine has been changed.

This change is expected to improve reliability and performance for sites that use the IndexedDB API.

In a future phase, _existing_ data stores will be migrated from using LevelDB stores to SQLite stores.

See also:
* [IndexedDB API](https://developer.mozilla.org/docs/Web/API/IndexedDB_API) at MDN.
* [SQLite](https://www.sqlite.org/).


<!-- ------------------------------ -->
#### WebGPU: fragment depth

In WGSL, you can now provide a `less` or `greater` modifier to `@builtin(frag_depth)`.

Previously, `@builtin(frag_depth)` could potentially negatively impact performance, due to disabling the early-Z optimizations on a draw call.

The new modifiers allow explicitly setting the buffer mode, and allow the early-Z optimizations to be applied.

See also:
* [WebGPU API](https://developer.mozilla.org/docs/Web/API/WebGPU_API) at MDN.
* [frag_depth](https://gpuweb.github.io/gpuweb/wgsl/#frag-depth-builtin-value) in _WebGPU Shading Language_.


<!-- ------------------------------ -->
#### WebRTC Diagnostic Logging API

The WebRTC Diagnostic Logging API allows you to trigger the collection of WebRTC diagnostic data, so that the data can be used for local debugging.

If the user authorizes sharing the diagnostic data with the browser vendor, the API allows this sharing.  This provides you with information that can help fix bugs in the browser, or otherwise improve the browser.

WebRTC applications often encounter complex connectivity or media quality issues that are difficult to reproduce in local environments.  The WebRTC Diagnostic Logging API can help debug these issues.

See also:
* [Diagnostic logging](https://w3c.github.io/webrtc-extensions/#diagnostic-logging) in _WebRTC Extensions_.
* [WebRTC Diagnostic Logging API](https://wicg.github.io/webrtc-diagnostic-logging/).


<!-- ------------------------------ -->
#### WebTransport `headers` and `responseHeaders`

When calling the `WebTransport()` constructor, the `headers` option allows you to pass custom HTTP request headers to the server during the initial `CONNECT` handshake.

The `responseHeaders` property on the `WebTransport` object instance allows you to inspect the HTTP response headers that are sent by the server after the initial `CONNECT` handshake.

These additions to the WebTransport API allow you to:
* Supply metadata, authentication tokens, and custom parameters during the initial `CONNECT` handshake.
* Access server-provided headers, after the connection is established.

This change addresses several technical limitations in authentication, routing, and capability negotiation.

Without custom headers, you must either:
* Pass authentication tokens in URL query strings, which exposes credentials in server logs and telemetry.
* Authenticate over an initial data stream, which adds an additional round trip before the connection is usable.

Furthermore, API gateways and reverse proxies typically inspect HTTP headers at the CONNECT layer.  Without custom headers, these intermediaries cannot authorize or route WebTransport sessions via existing pipelines, forcing servers to accept connections before verifying credentials.

See also:
* [WebTransport API](https://developer.mozilla.org/docs/Web/API/WebTransport_API) at MDN.
